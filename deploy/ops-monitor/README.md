# IKUN 异常通知部署与回滚

本目录是部署包，不代表已在生产安装。先完成本地回归，再按原计划进行至少24小时生产影子验证和24小时小范围通知观察。真实飞书和邮件接收需要指定测试收件人；模拟平台通过不能替代实际收件。

## 模块边界

网关仅增加有界被动观测，关闭 `OPS_OBSERVATION_TOKEN` 即停止观测。独立 `ops-monitor` 进程持有 SQLite、规则、通知凭据；业务库仅授权 `ops_monitor_v1_*` 列裁剪视图。不执行账号、资金、网关重启或付费模型探测。无外部整机存活探测；整机、同机网络、监控进程与状态库同时失效时不能保证通知。

## 文件与权限

- 二进制：`/opt/ikun-ops-monitor/ops-monitor`，root所有，0755。
- 创建固定非root系统用户/组 `ops-monitor`；记录数值GID用于网关容器补充组。
- 凭据：`/etc/ikun-ops-monitor/monitor.env`，root:ops-monitor，0640；父目录0750。按 `monitor.env.example` 配置，不把真实值写入Git、命令参数或普通日志。
- 本地状态：`/var/lib/ikun-ops-monitor`，ops-monitor所有，0700，SQLite0600。
- 运行目录：`/run/ikun-ops-monitor`，ops-monitor组可进入；socket0660。网关仅挂载这个运行目录并加入对应组，不共享状态库或凭据目录。
- `nginx-deny.conf` 应合入所有对外站点并经过 `nginx -t`。先确认外部请求无法访问观测快照，再启用token。

## 只读数据库接入

1. 通过现有迁移流程应用 `backend/migrations/274_ops_monitor_readonly_views.sql`；先在隔离库检查对应版本表结构。不要在已有生产库直接重跑测试fixture。
2. 由数据库管理员执行 `grants.sql`，再单独创建LOGIN凭据并授予该只读角色。登录凭据通过受限文件注入；禁止在终端打印密码。
3. `OPS_POSTGRES_DSN` 指向本机15432端口，使用专用LOGIN。验证业务表SELECT和所有业务写入均被拒绝；仅视图查询成功。实际表列与适配版本不符时，显示M01覆盖缺失，不回退读取敏感原表。
4. 运行数据库账号只有1连接，每查询最多3秒、每页500行；初次历史仅归档。对账迟到窗口24小时，超过窗口不保证补齐。

## 构建与启动

在完整测试通过的源码版本构建 `backend/cmd/ops-monitor`，保留Go版本、commit、二进制SHA256。将systemd服务文件安装后 `daemon-reload`、`enable --now`。检查127.0.0.1:9188/health、Unix socket权限、独立服务journal；不要将health端口映射到外网。

最新只读复核已确认8080由子进程运行干净的f44e588，与实施基线一致；早先a829efb/dirty元数据来自旧父进程，不是服务工作进程。升级时仍须再次核对监听PID与二进制SHA，并保存当前运行文件和启动配置以便回滚。只部署监控进程无法获得新埋点信号，生产影子必须使用同一已验证版本的网关适配层。

`OPS_BUSINESS_TIMEZONE` 必须与网关 `timezone` / `TZ` 一致，默认业务值是Asia/Shanghai。只读事务按该时区计算日重置；周/月分别按168/720小时滚动重置，不修改业务计数。

## 通知通道页面配置（2026-11-24）

飞书机器人（App ID/Secret，国内版或 Lark）和邮箱 SMTP 现在在后台「异常通知 → 通知设置 → 通知通道」填写，保存即生效、无需重启。密钥以 AES-GCM 加密存入监控 SQLite，密钥文件为状态目录下 `channel.key`（0600，首次启动自动生成；备份状态库时一并备份，丢失后需在页面重新填写密钥）。页面从未保存时继续使用 monitor.env 中的 `OPS_FEISHU_*` / `OPS_SMTP_*`。保存飞书凭据时会调用飞书接口验证；「从飞书选择群」需要应用开通 im:chat:readonly；「发送测试通知」直接发送一张测试卡片/邮件。邮件只发 P0/P1 的新故障、升级和恢复，不发普通更新。

## 飞书通知

创建飞书自建应用，启用机器人，发布所需权限，选择可用范围内的本人open_id作为私聊目标；只有选择群通知时才需将机器人加入指定群。第一阶段只需要消息发送与卡片更新；不启用消息指令或操作回调。在通知通道中配置 App ID/Secret；收件群oc_或用户ou_在后台“异常通知→通知设置”配置。先发送测试发生/更新/恢复卡片，核对实际接收与权限，再启用真实规则。

飞书固定业务uuid在重试中复用；平台去重时间窗口有限，长时间网络不确定性仍可能重复。消息更新失败时仅在明确消息不存在的情形重新创建；权限错误不冒充成功。失败记录保留可查，不无限重试。发送器本身失败不递归产生无限M02。

## 接管与回滚

默认所有规则notification_owner=legacy且shadow=true。在通知设置填写按规则/分组/模型/精确事件范围的负责人，以及已核对的旧规则ID→新规则映射。旧规则仅有分组/平台维度，映射必须完整覆盖对应范围；存在仍由旧模块负责的例外时，不抑制旧发送。不要清空旧规则或改写旧历史。

配置权威来源只有监控SQLite。监控将无凭据的 `ownership.json` 原子写入运行目录，网关旧邮件出口只读该投影；不共享业务库写权限。切换先发布新旧抑制范围并集，再提交配置，再发布当前范围；回退先停止新发送后恢复旧出口。配置CAS冲突会重建权威投影；进程重启及每轮评估会修复未完成发布。运行目录由systemd保留。读不到投影时，已启用此接入的旧发送器暂停发送并记录安全错误分类，防止盲目双发；部署时必须先启动监控并验证投影可读。

暂停新通知：后台切回影子模式，会恢复旧出口。局部回退：将该范围负责人改回legacy。已经进入网络发送的消息不可撤回，因此并发切换无法承诺跨进程严格一次；停机中断也可能形成短暂通知空档。保存配置版本及旧规则快照，真实交接仍需测试收件核验。

网关回滚恢复保存的实际运行二进制与启动配置、移除观测token并重启网关；独立监控可保持运行报告采集缺失。监控回滚前检查SQLite schema兼容，版本1之外的更高schema会拒绝启动，不强行降级数据库。

## 备份、恢复与容量

SQLite使用WAL。离线备份：先暂停监控服务，再运行二进制 `-state <state.db绝对路径> -backup <全新备份绝对路径>`；命令拒绝覆盖已有文件。完成后恢复服务，记录停机窗口。不要只复制正在运行的主db文件而遗漏WAL。测试覆盖VACUUM INTO一致快照与重开校验；在线定时备份仍需后续接入，不据此宣称已经运行。

恢复：停服务，保留原db/WAL/SHM为独立副本，在新目录验证备份可打开后再切换state路径；保留原件直到回归结束。离线服务停机期间无法通知。原始观察、事件历史、已完成投递保留 3 天，任务事实与配置变更记录保留 90 天；待投递事件的关联证据保留到投递结束，单SQLite上限约1GiB；达到上限或磁盘不可写时不能承诺通知队列继续落盘。

## 如何读通知

“已确认事实”来自结构化观测；“推断/缺失”给出证据边界。429不直接等于额度用完，取消不直接等于VPN故障。请求切换成功不关闭原账号故障。代理汇总等待关联账号全部有恢复证据，冷却结束不等于恢复。

确认只表示已看到；静默不代表恢复，新严重度升级仍提醒；人工关闭需原因，再次命中会重开。配置编辑有版本冲突检测，阈值变化保留旧规则结论。低水位不配置即不启用；正常Key自设日限额归档，用户资金来源额度耗尽仍提醒。

## 独立页面与容器权限

独立前端位于frontend/monitor-standalone，使用其Vite配置构建至monitor-dist，部署到/srv/ikun-ops-monitor/ui；nginx-standalone.conf加入同源站点。管理员自定义菜单指向/ops-monitor-ui/，原运维页面不加载监控组件。静态页面无业务数据，数据接口仍要求管理员会话。URL不携带token，使用同源已有登录会话。

容器需明确user: "1000:1000"并保留group_add监控GID；否则入口su-exec会丢掉附加组。验证实际业务进程/proc/PID/status的Groups以及经过认证的管理员代理，不用docker exec id代替。
