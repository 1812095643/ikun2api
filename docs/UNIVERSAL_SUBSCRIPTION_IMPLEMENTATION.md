# 通用订阅、站点名称与 Claude 账号白名单

基线：`24ffe44`；实施日期：2026-11-04。当前工作为本机实现与验证，未发布版本、未部署生产。

## 产品规则

- 新订阅是独立的限时额度：管理员设置售价、有效天数、总额度和可选的日、周、月上限。
- 计费金额仍为现有倍率后的实际 USD 费用。套餐售价、支付币种、使用额度是不同字段，不把支付金额当成模型用量。
- 一名用户同一期的全部订阅 Key、全部已授权分组共用额度。专属分组仍需用户已有的明确授权，不因购买全站套餐而自动取得权限。
- 日额度按站点时区零点刷新，周按 7 天、月按 30 天滚动。周期刷新不恢复总额度；最后不足一个周期时显示本期结束时间。
- 到期、总额度用尽、周期达限或管理员停用后停止请求。没有余额接续选项，不会转扣普通充值余额。
- Key 必须明确选择普通余额或通用订阅。允许同一用户有用途不同的 Key，来源不同的 Key 不互相补扣。
- 同时只有一份通用订阅生效；续购与再次发放按现有有效/停用订阅的最晚结束时间排期。退款与撤销不擅自改变其他订单已经排定的时间。
- 下单、发放和生成订阅兑换码时保存完整规则快照。之后编辑销售套餐，不改变已有订单、用户权益和兑换码的额度。

## 入口与职责

| 入口 | 内容 |
| --- | --- |
| `/admin/subscriptions` | 套餐档位、用户订阅及记录、旧订阅存档 |
| `/admin/orders/plans` | 同一份套餐配置的兼容入口，不另建商品库 |
| `/purchase?tab=subscription` | 选择套餐并通过既有支付流程付款，确认后自动开通 |
| `/subscriptions` | 总额度、剩余、周期用量、预留、排期与到期时间 |
| `/keys` | 单条及批量设置计费来源；引导说明如何选择 |
| `/admin/redeem` | 按通用套餐生成兑换码，原余额等兑换码流程保留 |
| 用户管理的订阅栏 | 跳转到按用户 ID 筛选的新订阅管理 |

路由视图只组合组件。套餐编辑、用户表格、发放、调整、用户卡片和进度条各自独立；`useUniversalSubscriptions` 负责加载状态和刷新。

## 旧订阅切换与上线准备

旧 `user_subscriptions`、旧套餐、旧兑换码、订单和用量记录都保留；原界面代码保存在 `LegacySubscriptionsView.vue`，不再注册使用入口。旧管理读取接口可查存档，写入接口拒绝继续发放/续期/重置。旧用户 active/progress 接口标记弃用，不把历史权益展示成仍可用的新订阅。

迁移 `264_universal_subscriptions.sql` 会停止旧分组套餐销售，并在首次新增 Key 计费来源字段时，将原订阅分组下的 Key 标记为通用订阅；再次运行迁移不会覆盖管理员或用户后来主动修改的来源。

**旧分组订阅没有可无损折算的独立总余额，因此不会自动编造新额度，也不会自动扩大专属组权限。上线前需核对旧用户、旧未兑换订阅码和旧待付款订单，按原合同权益创建新套餐/发放新订阅并处理旧码。** 在新权益发放前，原订阅 Key 会停止，避免误扣普通余额。当前没有连接生产数据库执行该切换。

上线前备份数据库、程序与设置；新财务迁移落地后不要通过回退旧程序来绕过新账本。数据库恢复应覆盖权益、预留、结算明细与支付状态，不能只恢复一个余额列。

## 财务与并发

- PostgreSQL 事务和用户级事务锁统一序列化发放、预留、结算、退款与调整。
- 发放操作使用持久幂等编号并核对完整快照；支付订单、兑换码和请求结算都有独立唯一约束。
- 普通请求在发送前登记数据库预留；计费任务接管请求上下文及预留引用。多 Key 共享未结算占用，多个用量记录逐次减少同一请求的剩余预留。
- 预留采用现有定价器估算，结算记录真实上游用量。真实费用高于估算时全额记账并阻止后续请求，不丢账、不截断成零、不把差额转入普通余额。额度是请求准入与结算限制，不承诺任何估算永远精确。
- 无法定价、数据库不可用、没有已生效权益时拒绝新订阅请求，不走普通余额的缓存降级。
- 受理情况不明或进程中断的预留不会按超时直接当作免费释放。管理员记录页可核对后释放，操作要求原因并留痕。仍在执行的请求不能人工释放。
- 批量生图保存创建时来源，冻结/捕获/释放使用该来源，修改或删除 Key 不会改为扣钱包。
- 异步视频保存任务与用户、Key、来源、预留的绑定；后续查询、完成结算使用原绑定，其他用户/Key 不能取得它。
- 退款只处理原订单对应的权益批次，先冻结该期，再调用支付渠道；成功撤销、明确失败恢复、待确认则保持冻结。已消费套餐须明确复核；执行中或待核对请求不会被 force 直接跳过。
- 管理员调整额度不重置已用量，不能调低到已消费加预留以下；延长有效期不能与已排期的其他权益重叠。
- Redis 原有余额/用户平台限额/Key 限额机制继续保留，通用订阅的财务真值在数据库。

## 站点名称

前端由 `utils/branding.ts` 集中默认名；正常显示读取 `site_name`。中英文文案使用明确占位符，富文本中的名称先转义；新手引导、认证布局、教程、标题、后台文案、海报、客户端配置名称复用站点名。导出 TOML/JSON 和 HTML 按各自格式处理。

后台支付商品名称保留管理员覆盖值，未设置才回退站点名；工单邮件及新建验证器的发行方显示也读取站点设置，已有验证器密钥不变化。

保留的固定名字主要是：默认值/占位示例、源代码说明、仓库/更新/法律文档地址、协议类型和法律承诺的版本化原文。尤其不能把第三方上游类型 `sub2api`、客户端 provider 标识、配置键和已确认的承诺短语做全局字符串替换。

## Claude 账号白名单

- 使用 `accounts.extra.model_allowlist = { enabled, models }` 独立保存，不借白名单修改现有模型映射或 OAuth 协议。
- 新增、编辑和批量编辑复用现有模型选择组件，默认关闭。开启而未选模型会被服务端拒绝。
- 使用既有 Claude 模型等价规则处理短名和完整 ID，支持通配符；不把所有未知模型做模糊放行。
- 普通调度、固定会话、直接转发、计数和热身遵守限制；模型列表独立读取当前管理策略，同时保留旧模型合并与短缓存行为。
- 分组准入和账号准入同时生效。保留指纹、身份、代理、TLS、隐私过滤、工具名处理、签名修复及正常请求重试。

## 验证边界

验收记录保存于当前工作区 `outputs/ikun2api-universal-20261104/`。数据库测试使用本机隔离 PostgreSQL 的随机 schema；界面使用合成 API、合成用户和虚构金额，不连接生产接口。

已覆盖快照编辑、续购排期、事务回滚、多 Key 并发、去重结算、旧 Key 迁移意图、到期/停用、未知预留、原订单退款、异步来源固定与跨用户隔离；兑换码另外通过实际仓储验证生成、并发一次性使用和发放失败回滚。

没有发送真实支付、退款、邮件或付费模型请求。编译/回放/合成界面通过不能替代上线后的真实链路验收。
