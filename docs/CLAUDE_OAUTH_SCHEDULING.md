# Claude OAuth 排队与会话调度

基于 PR #1（7aa164b）重整到 IKUN2api 1.5.1（415f0c2），仅 `platform=anthropic` 且 `type=oauth` 生效。Setup Token、Claude API Key、OpenAI、Gemini、Grok、Antigravity 保持原调度；混合池只重排 OAuth 所在位置，等待替代账号也只从 Claude OAuth 选取。

- 新会话、缓存已冷或原账号不可调度时，优先使用 5h/7d 用量低于 85% 的账号；全部超过软阈值时继续调度。原有账号暂停、模型冷却、额度、RPM、利润控制和分组限制继续生效。
- 热会话依据 `(排队人数 + 1) × 最近平均占用时间 / 并发` 决定是否等待原号。小于 200000 字节不独占等待，普通预算 1.5 秒，大于等于 800000 字节预算 4 秒，硬上限 10 秒；这些是开放替代账号的宽限期，不是总排队上限。模型路由和普通调度使用相同规则。
- 粘性缓存是否仍热，以绑定 Redis TTL 推算的距上次成功使用时间为启发式，默认窗口 5 分钟；该值不是上游缓存命中的证明。
- 排队先读实时压力，再关注至多 8 个替代账号。本实例释放槽位时主动唤醒，跨实例继续由轮询兜底。
- 拿到槽位后读取最新账号数据，重查账号类型、分组归属、并发配置、模型支持及冷却、配额、渠道限制、RPM、窗口费用和会话限额。失效候选释放槽位；全部失效及时结束等待。
- 选号和失败转发不覆盖绑定，成功转发后才绑定实际承接账号；利润控制场景继续保护既有绑定。
- 槽位时长采样仅用于 Claude OAuth。关闭 `gateway.scheduling.fallback_wait_any_account` 或关闭负载感知可恢复原调度；软阈值可单独设 0 关闭。
- 新增 270/271 迁移仅增加可空的耗时列，保留 30 分钟、12 小时缓存用量等主线字段。仅 Claude OAuth 写入新计时，其他账号及旧记录回退原首字口径。吞吐量仍使用上游耗时，显示的总耗时才加转发前等待。

验证包含账号类型矩阵、混合池位置、功能关闭、软阈值兜底、缓存等待、等待后冷却与暂停复核、成功后改绑、并发唤醒、SQL 列序、旧用量回读及前端吞吐量。CI 在隔离 PostgreSQL/Redis 上执行迁移与用量持久化测试，并在 Linux 使用 race 检查；不对真实账号发送测试模型请求。
