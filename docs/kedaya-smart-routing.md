# API Key 智能路由与渠道状态卡片

功能参考：[kiss-kedaya/sub2api](https://github.com/kiss-kedaya/sub2api)，提交 `c33708f17b89975cf6a3e88a6f3ff9d41a53884d`（2026-11-08）。保留原项目 LGPL-3.0 许可；有序候选 ID 的归一化逻辑由其实现适配。

## 使用

新建或编辑 API Key，开启「智能路由」，添加并排序分组。单组 Key 的行为不变。分组筛选可匹配备用分组。管理员删除或迁移分组时，会维护候选顺序并提升新的主分组。

每次尝试都使用原有网关的完整认证、IP 限制、分组权限、模型白名单、客户端限制、账号调度、在途预留与计费管线。记录和费用属于最终处理请求的分组。CC-Switch、Magpie 通过本 Key 的模型发现接口获取合并后的模型列表，保留原有导入选项。服务端使用上下文绑定候选，不接受客户端指定内部路由 ID。

只有本地模型/协议不匹配、组不可用或调度器确认账号耗尽时，才尝试下一组。普通上游错误不作为换组依据；输出已开始后不重放。模型发现合并已通过认证与权限检查的候选目录并去重。WebSocket 在首个 `response.create` 帧到达后按实际模型选择候选组，绑定该组的策略与计费，再复用现有连接与会话亲和；后续帧不跨账号/分组迁移。

迁移 `268_api_key_smart_routes.sql` 为 API Key 增加可空 JSONB 字段，与主分组同一行原子更新。旧 Key 无需回填；认证缓存版本提升至 29。

## 渠道状态

被动监控默认采用厂商分区卡片，支持 90m、24h、7d、30d、个人倍率、缓存率、可用率、首 Token 和带时间明细的历史条。沿用 IKUN 配色，保留「详细统计」。主动探测模式保留原有指标、详情、刷新间隔及开关，并使用紧凑工具栏和厂商分区。

缺失时间段按真实时间补空槽；没有样本的指标显示空值。继续使用服务端监控分组权限与脱敏输出，不读取上游凭据。
