# Claude 7d 临近重置优先调度

管理员在分组管理中新建或编辑 Claude（Anthropic）分组时，可设置「7d 时间临近优先调度」。新分组与升级前已有分组默认开启，其他平台不使用此策略。

- 开启后，通过现有账号状态、限流、模型、额度、费用、RPM、利润等准入检查的候选，在原有优先级阶段叠加 7 天剩余时间的高权重得分，剩余时间越短得分越高，足以覆盖手动账号优先级。示例：7h → 2d → 4d → 5d。
- 最近重置的候选并发已满、抢占失败或会话数量限制不允许时，继续尝试后续候选，不突破并发上限。
- 时间得分与现有优先级一起参与选择，不重写调度流程。同一重置时间使用原有优先级、负载、LRU 等规则；缺失、无效、已过期或已耗尽的窗口不获得此项优先权。没有可优先的窗口时使用原规则。
- 关闭后恢复原有调度顺序。账号原始优先级不被改写。
- 已绑定会话仍使用现有亲和机制；模型路由、分组隔离、故障切换和限流条件继续生效。切换分组设置不会主动迁移正在使用的会话。

7d 时间来自既有主动用量查询与响应头被动采样同步写入的 `passive_usage_7d_reset`，不使用 5h 的 `session_window_end` 代替，不为排序增加上游请求。

管理接口字段为 `prefer_soonest_weekly_reset`：创建时省略表示默认开启；更新时省略表示保持；显式 `false` 关闭。配置随分组持久化，复制分组保留该值，修改设置失效认证缓存；旧版缺少字段的认证快照会重新加载。普通用户分组响应不提供该内部配置。

数据库前向迁移：`266_group_prefer_soonest_weekly_reset.sql`。
