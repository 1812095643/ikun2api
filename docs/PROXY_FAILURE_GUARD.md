# 代理故障保护

绑定代理的账号遇到连接失败、代理认证失败、传输超时、响应读取中断或 Claude SSE
未收到结束事件即断开时，停止该账号的当前请求，并取消本进程中该账号的其他在途请求。
不将普通上游 400、401、403、429、5xx 或用户主动取消当成代理故障。

## 冷却与恢复

- 故障立即写入账号 `extra.proxy_failure_guard`，并设置最短三分钟的临时不可调度时间。
- 调度读取持久化标记；三分钟到期、进程重启、手动清空普通冷却均不能直接放行。
- 后台串行检查：冷却结束后，经账号当前有效代理向原目标的 origin 发无凭据 HEAD
  请求，保持 TLS 证书验证并禁止跟随重定向。不调用模型、不刷新 token 来探测。
- 探测失败继续停调；成功后比较故障 generation、账号代理 ID 和代理 updated_at，
  只有当前代理与本次探测一致才能清理标记。保留其他冷却、限额、封禁和手动暂停。
- 持久化写入失败时，本进程继续拦截并在检查任务中重试；读取当前账号或代理失败
  直接拒绝出站。其他实例的新请求同样读持久化标记，本进程的在途请求直接取消。

## 出口约束

普通 HTTP 与 TLS 指纹出站共用发送前校验，代理未加载、停用、过期、URL 变化或
传入空代理时拒绝发送。Claude OAuth/setup-token 缺少代理也拒绝发送。
模型请求、账号额度查询、遥测、管理员测试及 Claude token 刷新使用该保护。
Claude reset 查询/手动领取的生产发送同样经过此出口校验，不改变其幂等保护。

旧配置中的代理到期 `fallback_mode=direct` 不再自动清除账号的代理绑定；显式备用
代理仍可保留，但不能以直连作为链尾。代理故障后清理相关客户端缓存和空闲连接，
恢复使用新连接。原来明确配置为无代理的其他供应商账号不由此强制增加代理。

## 验证与边界

本地测试覆盖 HTTP/HTTPS 目标、TLS 指纹启用/关闭、代理离线时目标零连接、407、
同账号取消、流空闲超时、SSE 中断/完整终止、重启后停调、最短冷却、探测失败不放行、
旧故障及代理配置并发变化、管理编辑不能删除运行态标记。数据库更新通过带条件的
单条 CTE 同事务写入账号与调度 outbox。

网络故障在操作系统或传输超时报告后才能判定；不能在尚无信号时声称检测已发生。
这里验证应用的代理路由与恢复状态机，不证明供应商账号安全，也不验证外部代理
自身的路由策略。未通过中断生产代理或发送付费请求进行验收。
