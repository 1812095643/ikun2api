# 记账收款与下游管理

## 管理入口

- 用户管理 → 充值：勾选「记账跑付」，增加余额并记录同额待收款。
- 用户管理 → 创建/编辑：可切换「设为下游」，默认关闭。用户列表支持下游筛选。
- 记账收款：按用户汇总累计记账、已收款、待收款；支持未结清/已结清筛选、部分收款、全部结清和往来明细。
- 下游管理：查看余额、欠款、各分组专属倍率、区间请求数、Token 和消费；支持单个及批量调价、充值、用量明细和移出下游。
- 渠道定价：每张模型价卡可勾选「对代理生效」，已有配置默认开启。

## 倍率规则

下游仅是用户的管理属性，不划分等级、档位，不预设倍率。快捷调价写入原有 `user_group_rate_multipliers`，与用户管理中的分组专属倍率为同一份数据。修改某个分组不影响其他分组；恢复分组倍率保留已有 RPM 覆盖。

渠道价卡关闭「对代理生效」后，下游跳过该渠道价卡，按原有定价解析链继续回落，再套用原有用户分组倍率。显式分组模型价卡保留原有优先级。普通用户、账号成本统计和官方参考价的规则不因下游标记改变。输入、输出、缓存、区间与渠道分时等价格取自同一次解析；用量扣费、余额预留和展示使用相同的身份口径。

## 记账规则

余额与记账使用相同的 USD 单位，最多八位小数。记账充值金额是本次待收款，登记收款只减少欠款，不重复增加余额，也不重做充值返利。

记账充值的余额、充值流水和欠款在同一个 PostgreSQL 事务提交。收款先锁定用户和操作编号，拒绝超额收款。操作编号持久化，不依赖短期请求缓存，重试不重复记账。每条流水保留经办人、时间、备注、收款方式和当时欠款；用户软删除不会抹掉欠款。

## 权限与升级

两个页面均由管理员路由和后端管理员认证保护，受限管理 Key 无权访问新页面或修改下游身份。普通用户 DTO 不包含下游属性。菜单显示开关不改变后端权限。

新增迁移 `272_admin_receivables_downstreams.sql`，保留历史数据和现有倍率。新增 `on_account` 充值来源，不把未收款计入抽奖的已付款充值条件。没有修改历史迁移。

## 组件职责

- `ReceivableManager` / `DownstreamManager`：筛选、分页、列表加载与操作协调。
- `ReceivableTable` / `DownstreamTable`：展示记录与触发操作。
- `ReceivablePaymentDialog`：新鲜欠款校验和收款登记。
- `ReceivableHistoryDialog`：按用户分页查看往来流水。
- `DownstreamActionDialog`：添加、移出及现有分组倍率的单个/批量编辑。
- `DownstreamUsageDialog`：当前统计区间的分组/模型用量汇总。
- `useBusinessRequest`：取消旧请求，阻止过期响应覆盖当前对象。

## 验证边界

本地 PostgreSQL 17 独立实例验证了重复充值、部分收款、结清、并发超收保护、写入失败回滚、批量调价及 RPM 保留。浏览器使用本地合成数据检查桌面、390px 手机、明暗主题和弹窗交互。没有使用真实用户余额、真实上游付费调用或修改线上服务器。
