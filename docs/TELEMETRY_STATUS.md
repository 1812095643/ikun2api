# Claude 遥测隐私处理

2026-10-27 按用户要求采用 Go 实现，恢复受限的脱敏上报。安装示例默认关闭，108 已开启 `SUB6_CLAUDE_TELEMETRY_ENABLED=true`。不新增 Python 或 Rust 遥测程序。

## 触发和定时发送

- 原始客户端遥测在网关终止，只读取事件种类和本地关联所需的会话、事件 UUID。Git、路径、哈希、提示词、工具内容和客户端附加元数据均不转发。
- 只为真实完成的 Claude OAuth / setup-token 模型请求保存最小脱敏摘要。同一 Key、客户端会话和结果类别仅保留最近一份；身份必须与服务器账号指纹及重写会话匹配。
- 客户端同身份事件可以立即领取摘要；定时任务采用本机官方 Claude Code 2.1.301 的内部事件默认延迟 10 秒，从首份真实摘要进入队列开始计时；空队列不启动定时器。持续请求更新摘要时不顺延首次到期时间。官方灰度配置及 `OTEL_LOGS_EXPORT_INTERVAL` 可以覆盖官方客户端的默认值，本实现采用已核实的默认值，不读取客户端的间隔字段。
- 两种触发方式共用互斥领取，一份摘要最多发送一次。没有新请求时不发送；不产生虚构启动、项目维护或工具活动。来源明确为 `ikun2api_gateway`。
- 同一 Key、用户、分组、上游账号、令牌、代理、UA、TLS 配置及设备身份的到期摘要合并发送；单批最多 200 条且不超过 256 KiB，不同身份分批。客户端触发和定时任务都复用此规则，`queued_count` 仍表示事件数。
- 摘要保留 10 分钟，缓存最多 2048 条；待发送及发送中的批次合计最多 16 个。定时和客户端触发共用进程内唯一 HTTP 发送槽，所有 OAuth / setup-token 账号全局最多同时发送 1 批，上一批结束后至少等待 2 秒再发送下一批。此间隔属于网关限流策略，不改变默认 10 秒摘要调度，也不是官方频率。
- 排队不占用单次 HTTP 的 10 秒超时；取得发送槽之后重新核对身份与代理。过期、满队列、退出及发送失败均允许丢弃，不自动重试；不承诺完整遥测记录。退出同时取消正在发送和等待发送的任务。
- 每个账号只发送自己的实际结果、用量和服务端身份，保留各自独立的事件 ID、会话和时间；不为内容差异捏造使用量或活动，实际统计数值可能相同。

## 身份和出口

发送前重新读取本地 Key、用户及分组状态，并核对上游账号、账号 UUID 和代理。原请求身份已停用、被删除或分组变化时丢弃摘要；不重复计费，不更新 Key 使用时间。请求耗尽余额或额度不影响其已完成摘要的处理。

只复用账号实际模型请求的代理和 TLS，代理缺失、停用、过期或发生变化时停止发送，禁止改用服务器公网直连。用户说明其位于新加坡并使用新加坡代理；本功能保留既有出口，不依据代理地址推定用户国籍。

固定目标为 `https://api.anthropic.com/api/event_logging/v2/batch`，不跟随重定向。只有上游明确返回 `accepted_count` 等于本批事件数才记录整批接收成功；部分接收保留实际确认数，不重发整批。缺失、重复字段、越界数量、超大或含额外 JSON 的回执均视为未确认，本地入队或 HTTP 200 不能代替确认。

服务退出时取消定时器和在途发送，并清理内存摘要。客户端自行直连其他遥测地址不经过网关，本功能不能拦截该类流量。

## 证据范围

本机 Claude Code 2.1.301 的内嵌 JavaScript、隔离样本及上一轮回放位于任务目录 `outputs/claude-telemetry-audit-20261027`。定时发送回归与部署证据位于 `outputs/claude-telemetry-scheduler-20261027`。本地测试接收器的确认不等于供应商接收，不据此推断账号安全或供应商采集行为。

适当对齐官方 2.1.301 的批量发送形态，不增加事件类别或个人信息字段。客户端 gzip 由条件回调启用，网关维持现有 JSON 发送；官方部分路径在 401 后改为匿名发送，网关继续保留鉴权和无重试限制。批量验证证据位于 `outputs/claude-telemetry-batching-20261027`。
